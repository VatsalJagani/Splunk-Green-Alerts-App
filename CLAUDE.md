## What This App Does

A Splunk App that generates **green alerts** (notifications when issues resolve) alongside red alerts (when issues occur). It tracks per-alert state transitions across search runs using two KVStore collections.

## Build, Lint, Test, Deploy

There is no Makefile or local build script. All CI/CD is handled by GitHub Actions via the `VatsalJagani/splunk-app-action` reusable action:

- **On PR** (`.github/workflows/on_pr.yml`): Runs local Splunk app inspection (linting) and validates `lib/requirements.txt`.
- **On push to `develop`** (`.github/workflows/on_main.yml`): Generates app utilities (`whats_in_the_app`, `logger`), runs app inspection, and uploads to Splunkbase.

To trigger validation: open a PR against `develop`. There is no way to run these checks locally without the GitHub Action runner.

## Architecture

### Core Flow

1. A user's saved search appends `| greenalert <alertname> <statusfield> <groupbyfields>` to its SPL.
2. **`bin/green_alert_cmd.py`** (streaming custom command) processes each result row:
   - Queries `green_alerts_details_collection` KVStore to get/set the group-by field schema for this alert.
   - Queries `green_alerts_data_collection` KVStore to read the previous state (`RED`/`GREEN`) per unique group.
   - Applies transition logic:
     - **RED → first RED**: suppress (already alerted)
     - **GREEN → RED**: yield row (new problem — red alert)
     - **RED → GREEN**: yield row (problem resolved — green alert)
     - **GREEN → first GREEN**: suppress (steady-state OK)
   - Updates the KVStore entry with the new state.

### Key Files

| Path | Purpose |
|------|---------|
| `bin/green_alert_cmd.py` | Main command logic |
| `bin/logger_manager.py` | Centralized logging (auto-generated by splunk-app-action, do not edit manually) |
| `bin/import_utils.py` | Adds `lib/` to sys.path for splunk-sdk |
| `default/commands.conf` | Registers `greenalert` as a chunked Python 3 streaming command |
| `default/collections.conf` | KVStore schemas for both collections |
| `default/transforms.conf` | KVStore lookup definitions referenced by the command |
| `default/searchbnf.conf` | Search assistant syntax hints and examples |
| `lib/requirements.txt` | Single dep: `splunk-sdk` |

### KVStore Collections

- **`green_alerts_details_collection`**: One doc per `alert_name` — stores `groupby_field_names` (comma-separated).
- **`green_alerts_data_collection`**: One doc per `(alert_name, groupby_field_values)` — stores `status` (`RED`/`GREEN`). Accelerated on `alert_name`.

### Logging

Logs write to `/var/log/splunk/greenalert_*.log` with sourcetype `greenalert:logs`. `logger_manager.py` is **auto-generated** by the CI action — edits to it will be overwritten on the next develop-branch push.
